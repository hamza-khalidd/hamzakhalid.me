01 · Agents

Agentic loop

An agent is not a long prompt. It is a loop that holds a goal, takes one step at a time, and checks the result before deciding what to do next.

The four moves

Every agent, however it is dressed up, repeats the same four moves. It holds a goal. It plans the next step. It acts. It observes what came back. Then it decides whether to go round again.

The goal is an outcome, not a method. "A weekly loss report" is a goal. "Run this query" is a step. Keeping the two apart is what lets the agent change its route when a step fails.

One step at a time

The plan is short on purpose. The agent picks the next concrete step from what it knows now, not the whole project up front. In the picture, that is one item on the checklist lighting up per pass.

Acting is where tools come in: a query, an API call, a draft. A running step is not progress yet. The tick only lands after the result has been checked.

The check is the point

Observing is the move people skip. It compares the result against the goal and answers one question: is there a gap left? "Two sites missing" is not a failure. It is the reason for the next pass.

A loop without a check either stops too early, with a wrong report, or never stops at all. The stop condition, "goal met", is what makes this an agent and not a script on repeat.

What to watch for

Cap the number of passes. Log every observation. And write the goal so it can actually be checked, because a goal the agent cannot verify is a goal it cannot finish.
